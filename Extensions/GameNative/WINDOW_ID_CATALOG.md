# 插件窗口 ID 与层级

业务插件不直接选择窗口 ID，只向 `GameNative` 声明需要的窗口数量和层级。

当前客户端窗口工厂覆盖 `0..907`。下列 ID 在工厂中走空分支，可以安全复用。工厂共 35 个空 ID，宿主按真实窗口锚点分层后全部开放。

层级按窗口 ID 递增分配。当前 ESC/系统菜单窗口是 `724`；高于它的空闲 ID 是 `772`、`835`、`838`。菜单打开时会被提到前台，这些层只表示编号更高，不会压住菜单。

## 可用层级

| 用途 | `afterWindowId` | 可分配 ID | 容量 | 编号范围 |
| --- | ---: | --- | ---: | --- |
| 低于装备栏 | `-1` | `18, 21, 48, 75, 99` | 5 | 低于装备栏 `119` |
| 装备栏附近 | `CLIENT_PATCH_WINDOW_ID_EQUIPMENT`（119） | `159, 170, 223, 272, 284, 287, 309, 314, 315, 316, 323, 324, 362` | 13 | 高于装备栏，低于旧中层窗 `364` |
| 中层弹窗 | `CLIENT_PATCH_WINDOW_ID_MID_POPUP`（364） | `389, 414, 523, 536, 569, 588, 589, 598, 599, 612, 614, 617, 618, 649` | 14 | 高于 `364`，低于当前菜单窗 `724` |
| 菜单编号之后 | `CLIENT_PATCH_WINDOW_ID_GAME_MENU`（724） | `772` | 1 | 编号高于当前菜单窗 |
| 更高空闲层 | `CLIENT_PATCH_WINDOW_ID_ABOVE_MENU`（834） | `835` | 1 | 高于 `834`，低于 `836` |
| 最高空闲层 | `CLIENT_PATCH_WINDOW_ID_PLUGIN_POPUP_TOP_ANCHOR`（837） | `838` | 1 | 高于 `837` |

## 申请示例

```cpp
int windowIds[2] = {};
if (!api.reserveWindowIds(L"ClientPatch.MyPlugin", 2,
    CLIENT_PATCH_WINDOW_ID_GAME_MENU, windowIds))
{
    return false;
}
```

申请规则：

- `owner` 必须稳定且唯一，不区分大小写。
- `count` 是插件需要的顶级窗口数量。
- 返回的 ID 不保证连续，插件必须保存宿主返回值。
- 同一 `owner` 重复提交相同请求会得到相同结果。
- 当前层容量不足时申请直接失败，不会自动跨到更高层。
- 工厂仍注册时不能释放 ID。

## 容量限制

可安全复用的 ID 已由宿主管理，业务插件不得硬编码其他空闲值。

当前一共可创建 35 个插件顶级窗口。需要多个页面时，应优先在一个窗口内使用
页签或子面板。容量耗尽后，需要在宿主中实现统一的虚拟窗口容器，不能简单增加 ID。
